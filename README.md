# lede

Minimalist git commit message generator. lede reads your **staged** diff, asks
an OpenAI-compatible API for a commit message, enforces the [50/72
rule](https://cbea.ms/git-commit/), and prints the message to stdout.

```sh
git add -p
git commit -m "$(lede generate)"
```

```bash
# Straight from GitHub:
cargo install --git https://github.com/eljpsm/lede

# With Nix:
nix run github:eljpsm/lede

# From a clone (installs to ~/.cargo/bin):
make install
```

## Usage

```sh
# Optional: write the default config and prompt, and check that a key
# resolves. Generating bootstraps the same files, so this exists for
# editing the config before the first real run.
lede init

# Create a message for whatever is currently staged.
lede generate

# Create a message with a hint.
lede generate "refactor only, no behavior change"

# Use a specific model and base URL.
lede generate --base-url http://localhost:11434/v1 -m qwen2.5-coder

# Commit the message directly.
git commit -m "$(lede generate)"
```

A handy alias for committing directly:

```sh
# This will commit the message generated by lede directly.
git config --global alias.ai '!git commit -m "$(lede generate)"'
```

## Configuration

On supported Unix systems, lede uses `$XDG_CONFIG_HOME/lede`, or
`$HOME/.config/lede` when `XDG_CONFIG_HOME` is unset or relative. Native macOS
locations and Windows are not supported.

On first run lede writes `config.toml` and `prompt.txt` there. The prompt
becomes user-owned. Later releases never replace it. Delete it to copy the
current default again.

```toml
# OpenAI-compatible API base URL (without the trailing /chat/completions).
base_url = "https://api.openai.com/v1"

# Model to request.
model = "gpt-5.4-nano"

# System prompt file, relative to this directory.
system_prompt_file = "prompt.txt"

[auth]
mode = "bearer"
# Name of the environment variable that holds the API key.
env = "OPENAI_API_KEY"
# Command run when the environment variable is not set.
# command = "pass show openai"
```

The environment variable wins when both sources are set. `command` suits a
password manager or keyring: `pass show openai`, `op read op://dev/openai/key`,
or `secret-tool lookup service openai`. It runs through `sh` and may prompt or
wait until interrupted.

Use no authentication for a local endpoint that does not need a key:

```toml
[auth]
mode = "none"
```

## Behavior

- Only the **staged** diff is sent (`git diff --cached`); lede errors if nothing
  is staged. Stage what you want described, then run it.
- The 50/72 rule is enforced twice: the system prompt asks for it, and lede
  verifies the output. An over-long subject gets one retry asking the model to
  shorten (then a word-boundary truncation as a last resort), and body lines are
  hard-wrapped at 72 columns.
- The default prompt asks for a subject only, even when several related files
  changed. It reserves bodies for large changes with distinct concerns, or
  essential context that cannot fit in the subject.
- The message is the only thing printed to stdout; diagnostics go to stderr and
  failures exit non-zero, so `git commit -m "$(lede generate)"` composes safely.
- Diffs larger than 64 KiB are truncated (the full staged file list is always
  sent, so the model still sees the commit's scope).
